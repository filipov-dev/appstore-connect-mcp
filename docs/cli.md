# Команды CLI

`appstore-connect-mcp` — один бинарник: MCP-сервер и команды для настройки. Справка по любой команде — `appstore-connect-mcp <команда> --help`.

См. также: [Ключ App Store Connect API](api-key.md), [Подключение к MCP-клиентам](clients.md), [MCP-инструменты](tools.md), [Безопасность](security.md).

## Профили

Профиль — это один кабинет App Store Connect: ключ API (`.p8`) и его настройки.

- Ключ хранится только в системном хранилище: Keychain в macOS, Credential Manager в Windows, Secret Service в Linux (GNOME Keyring, KDE Wallet, KeePassXC). Запись — сервис `dev.filipov.appstore-connect-mcp`, учётная запись — имя профиля. Файлового хранилища нет: в Linux без Secret Service команды завершаются ошибкой с подсказкой.
- Несекретные настройки — в `~/.config/appstore-connect-mcp/profiles.toml` (в Linux — `$XDG_CONFIG_HOME/appstore-connect-mcp/`, если переменная задана; в macOS тоже `~/.config`; в Windows — `%APPDATA%\appstore-connect-mcp\`): Key ID, Issuer ID (или `individual = true` для индивидуального ключа), номер поставщика для отчётов (`vendor_number`), MCP-клиент, в котором профиль подключён командой `connect` (`client`), права профиля (`allow_write`, `allow_destructive`, `allow_path`) и наборы инструментов (`toolsets`, `dynamic_toolsets`).
- Права профиля — граница доступа сервера: `serve`, `call` и `ui` не дают больше. Меняет их `appstore-connect-mcp ui` (или `connect --allow-write`/`--allow-destructive`, или правка файла). На macOS права сверх чтения действуют только после одобрения владельцем: одобренная копия прав хранится в Keychain (сервис `appstore-connect-mcp.access`, учётная запись — имя профиля), а `ui` и `connect` при повышении прав спрашивают Touch ID или пароль пользователя macOS. Понижение прав одобрения не требует. Если права в профиле шире одобренных, действует пересечение; если одобрения нет или Keychain недоступен — только чтение, сервер предупреждает в stderr. В Linux и Windows одобрения нет: права ограничивает роль ключа в App Store Connect ([Безопасность](security.md#уровни-доступа)).
- Имя профиля — флаг `--profile`, иначе переменная окружения `APPSTORE_CONNECT_MCP_PROFILE`, иначе `default`. Сам ключ из переменных окружения и `.env` не читается.
- Ни одна команда не выводит ключ и JWT.

## auth login

Сохраняет ключ API для профиля.

```
appstore-connect-mcp auth login [--profile <имя>] [--key-file <AuthKey_XXXXXXXXXX.p8>]
    [--key-id <ID>] [--issuer-id <UUID> | --individual] [--vendor-number <номер>] [--no-verify]
    [--no-input] [--no-browser]
```

- `--key-file` — путь к файлу ключа, скачанному в App Store Connect (Users and Access → Integrations → App Store Connect API). Ключ принимается только файлом: содержимое ключа аргументом не передаётся. Файл должен быть PEM PKCS#8 с ключом EC P-256 (`-----BEGIN PRIVATE KEY-----`).
- `--key-id` — Key ID ключа. По умолчанию берётся из имени файла `AuthKey_<KEYID>.p8`.
- `--issuer-id` — Issuer ID командного ключа (Team key); `--individual` — индивидуальный ключ (Individual key), у него нет Issuer ID. По умолчанию — как сохранено в профиле.
- `--vendor-number` — номер поставщика (Payments and Financial Reports) для отчётов продаж и финансов.
- `--no-verify` — сохранить ключ без проверки. Без флага ключ проверяется запросом `GET /v1/apps?limit=1`; если проверка не прошла, ничего не сохраняется.
- `--no-input` (синоним `--silent`) — тихий режим: ни вопросов, ни браузера, ни пояснений. Нужны `--key-file`, `--issuer-id` или `--individual` (если тип ключа не сохранён в профиле) и `--key-id` (если файл назван не `AuthKey_<KEYID>.p8`); чего не хватает, команда перечисляет в одной ошибке.
- `--no-browser` — не открывать ссылки в браузере, только печатать их.

**Пошаговый мастер.** В терминале без `--key-file` команда ведёт по шагам:

1. Что понадобится и зачем: файл ключа `AuthKey_<KEYID>.p8` (закрытый ключ, которым сервер подписывает короткоживущие токены; Apple даёт скачать его только один раз), Key ID (код ключа из 10 символов, он же в имени файла) и Issuer ID (UUID команды, общий для всех командных ключей). Кто может создать ключ: владелец аккаунта (Account Holder) или пользователь с ролью Admin; остальным ключ создаёт Admin.
2. Создание командного ключа: открывает в браузере страницу ключей App Store Connect (Users and Access → Integrations → App Store Connect API) и подсказывает, что нажать — запрос доступа к API (один раз, Account Holder), Generate API Key, имя, роль Admin, Download.
3. Файл ключа: после нажатия Enter ищет самый свежий `AuthKey_*.p8` в каталоге загрузок и предлагает его; иначе спрашивает путь (файл можно перетащить в окно терминала).
4. Issuer ID: подсказывает, где он на странице ключей (над списком, кнопка Copy). Пустой ответ — индивидуальный ключ.

Неверный ответ (нет файла, не ключ, не UUID) переспрашивается до трёх раз. Если App Store Connect отклонил ключ, можно сразу ввести Key ID и Issuer ID заново. После сохранения мастер предлагает (по умолчанию — нет) сохранить vendor number для отчётов продаж и финансов — открывает Payments and Financial Reports и подсказывает, где номер, — и показывает, как подключить сервер к клиенту. Если `--key-file` передан, а Issuer ID неизвестен, команда объясняет только, где взять Issuer ID, и открывает страницу ключей.

Ссылки не открываются по SSH, без графической сессии и с `--no-browser` — тогда они только печатаются.

После сохранения команда в терминале предлагает удалить исходный файл ключа (по умолчанию — нет: App Store Connect даёт скачать ключ только один раз). Без терминала (CI, скрипты) и с `--no-input` вопросов нет: недостающие значения — ошибка со списком флагов, файл не трогается. Повторный `auth login` заменяет ключ профиля.

## auth status

```
appstore-connect-mcp auth status [--profile <имя>] [--no-verify | --offline]
```

Показывает профиль, Key ID, тип ключа (командный с Issuer ID или индивидуальный), есть ли ключ в системном хранилище и результат проверочного запроса `GET /v1/apps?limit=1` (статус HTTP и число видимых приложений). С `--no-verify` (или `--offline`) проверяются только настройки и хранилище, без обращения к API.

Код возврата ненулевой, если профиль не готов к работе: нет Key ID или Issuer ID, нет ключа в хранилище или проверка не прошла.

## auth logout

```
appstore-connect-mcp auth logout [--profile <имя>] [--forget]
```

Удаляет ключ профиля из системного хранилища. Настройки профиля остаются; `--forget` удаляет и их. Если ключ больше нигде не нужен, отзовите его в App Store Connect.

## connect

Подключает сервер к MCP-клиенту одной командой: при необходимости сохраняет ключ профиля, записывает настройки доступа в профиль и регистрирует сервер в клиенте.

```
appstore-connect-mcp connect <claude-code|codex> [--profile <имя>] [--name <имя сервера>]
    [--scope user|project] [--key-file <AuthKey_XXXXXXXXXX.p8>] [--key-id <ID>]
    [--issuer-id <UUID> | --individual] [--vendor-number <номер>]
    [--allow-write] [--allow-destructive] [--toolsets <набор,...>] [--no-dynamic-toolsets]
    [--yes] [--no-verify] [--no-browser] [--no-input]
```

Ключ:

- Если у профиля уже есть ключ в системном хранилище и он проходит проверку `GET /v1/apps?limit=1`, он используется как есть. Повторный `connect` с другими флагами меняет только настройки профиля и запись в клиенте.
- Если ключа нет (или сохранённый не работает), команда ведёт по шагам тем же мастером, что [`auth login`](#auth-login): объясняет, что такое файл ключа, Key ID и Issuer ID, открывает в браузере страницу ключей App Store Connect и подсказывает, как создать командный ключ (роль Admin рекомендуется: с другими ролями часть инструментов не работает), находит скачанный `AuthKey_*.p8` в каталоге загрузок, показывает, где взять Issuer ID, проверяет ключ и сохраняет его. Если проверка не прошла, ничего не сохраняется. По SSH, без графической сессии и с `--no-browser` ссылки только печатаются.
- `--key-file` заменяет сохранённый ключ профиля ключом из файла; мастер при этом не показывается (если Issuer ID неизвестен — только подсказка, где его взять). Без терминала (CI, скрипты) и с `--no-input` ключ можно передать только через `--key-file`, а Issuer ID — флагом или из профиля.
- `--no-input` (синоним `--silent`) — без вопросов, браузера и пояснений; требует `--yes`. Запись с тем же именем, которая запускает другой сервер или другой профиль, в этом режиме не заменяется.
- `--key-id`, `--issuer-id`, `--individual`, `--vendor-number`, `--no-verify` — как у `auth login`; Key ID по умолчанию — из имени файла или из профиля.
- В самом конце, если ключ читался из файла в этом запуске, команда один раз предлагает удалить файл (по умолчанию — нет).

Регистрация в клиенте:

- Клиент получает только команду `<абсолютный путь к appstore-connect-mcp> serve --profile <профиль> [--toolsets …] [--dynamic-toolsets]`. Ни ключа, ни флагов доступа в конфигурации клиента нет: `serve` берёт ключ из системного хранилища, а права — из профиля.
- `--dynamic-toolsets` включён по умолчанию: агент подключает наборы инструментов по запросу. `--no-dynamic-toolsets` регистрирует сервер со всеми включёнными инструментами сразу.
- `--allow-write` ставит профилю уровень записи: инструменты, которые создают и меняют данные; `--allow-destructive` (включает и запись) — ещё удаление и действия с последствиями для пользователей App Store: отправку на ревью, выпуск версии, цены, пользователей и роли. Без этих флагов права профиля не меняются (у нового профиля — только чтение). На macOS повышение прав спрашивает Touch ID или пароль; при отказе профиль сохраняет прежние права, а ключ и регистрация всё равно сохраняются.
- `--toolsets` — наборы инструментов через запятую (передаются в `serve --toolsets`).
- Эти же настройки сохраняются в профиле (`client`, `toolsets`, `dynamic_toolsets`, а с флагами доступа — `allow_write`, `allow_destructive`).
- Повторный `connect` переписывает регистрацию старых версий, в которой были флаги доступа, на команду без них.
- Перед изменением команда показывает, что будет записано, и спрашивает подтверждение; `--yes` пропускает вопрос. Запись с тем же именем, которая запускает другой сервер или `appstore-connect-mcp` с другим профилем, с `--yes` не заменяется никогда: только после явного ответа в терминале. Остальные записи клиента не меняются.
- Claude Code: через `claude mcp add` (`--scope user` — для всех проектов пользователя, `--scope project` — в `.mcp.json` текущего каталога). Codex: таблица `[mcp_servers.<имя>]` в `$CODEX_HOME/config.toml` (по умолчанию `~/.codex/config.toml`), только `--scope user`; комментарии и форматирование файла сохраняются.

Имя сервера в клиенте (подробнее — [Подключение к MCP-клиентам](clients.md#имя-сервера)). Один профиль — один кабинет, поэтому имя сервера зависит от профиля: `appstore-connect` для профиля `default`, `asc-<профиль>` для остальных (точки в имени профиля заменяются на `-`); `--name` задаёт имя явно. Имя короткое, потому что клиенты называют инструменты `mcp__<сервер>__<инструмент>` и ограничивают это имя 64 символами, а имена инструментов бывают длиной до 40 символов: имя сервера должно быть не длиннее 17 символов (`appstore-connect` — 16, `asc-` + до 13 символов профиля). Для более длинного имени команда предупреждает: часть инструментов клиент может укоротить или отклонить.

Примеры:

```
appstore-connect-mcp connect claude-code
appstore-connect-mcp connect codex --profile work --key-file ~/Downloads/AuthKey_XXXXXXXXXX.p8 \
    --issuer-id <UUID> --allow-write --yes
```

## key exec

Запускает команду с ключом профиля во временном файле — для инструментов, которым нужен файл `.p8`: `xcrun altool`, `xcrun notarytool`, fastlane.

```
appstore-connect-mcp key exec [--profile <имя>] -- <команда> [аргументы...]
```

- Ключ записывается в новый файл `AuthKey_<KEYID>.p8` с правами 0600 в новом временном каталоге с правами 0700 (такое имя файла ищут `altool` и `notarytool`). В Windows прав Unix нет: файл и каталог наследуют права временного каталога пользователя (`%TEMP%` в его профиле, закрыт от других пользователей), сигналы команде не пересылаются; вместо `sh -c` используйте `powershell -NoProfile -Command '... $env:APP_STORE_CONNECT_KEY_PATH ...'`.
- Команда запускается без оболочки, stdin наследуется, с переменными окружения:

| Переменная | Значение |
| --- | --- |
| `APP_STORE_CONNECT_KEY_PATH` | путь к файлу ключа |
| `APP_STORE_CONNECT_KEY_ID` | Key ID |
| `APP_STORE_CONNECT_ISSUER_ID` | Issuer ID (для индивидуального ключа не задаётся) |
| `API_PRIVATE_KEYS_DIR` | каталог с файлом ключа (там его ищет `xcrun altool --apiKey <KEYID>`) |
| `APP_STORE_CONNECT_API_KEY_KEY_FILEPATH` | путь к файлу ключа — для действия fastlane `app_store_connect_api_key` |
| `APP_STORE_CONNECT_API_KEY_KEY_ID` | Key ID — для fastlane |
| `APP_STORE_CONNECT_API_KEY_ISSUER_ID` | Issuer ID — для fastlane (для индивидуального ключа не задаётся) |

- Сам ключ в переменные окружения не попадает. Унаследованные `APP_STORE_CONNECT_API_KEY_KEY` и `APP_STORE_CONNECT_API_KEY_IS_KEY_CONTENT_BASE64` (содержимое ключа для fastlane) убираются, чтобы команда не взяла чужой ключ; для индивидуального ключа убираются и унаследованные переменные Issuer ID.
- Аргументы команды не раскрываются: чтобы подставить переменную, запустите оболочку сами, в одинарных кавычках:

```
appstore-connect-mcp key exec --profile work -- sh -c 'xcrun notarytool submit App.zip \
    --key "$APP_STORE_CONNECT_KEY_PATH" --key-id "$APP_STORE_CONNECT_KEY_ID" \
    --issuer "$APP_STORE_CONNECT_ISSUER_ID" --wait'
appstore-connect-mcp key exec --profile work -- sh -c 'xcrun altool --upload-app -f App.ipa \
    -t ios --apiKey "$APP_STORE_CONNECT_KEY_ID" --apiIssuer "$APP_STORE_CONNECT_ISSUER_ID"'
appstore-connect-mcp key exec --profile work -- fastlane ios beta
```

- Ключ в stdout и stderr команды заменяется на `***`: целиком, по строкам и в base64 (`cat "$APP_STORE_CONNECT_KEY_PATH"` покажет `***`). Это страховка от случайного вывода, а не граница безопасности: преобразованный ключ (hex, другая разбивка на строки) не распознаётся. Не выводите ключ.
- Файл и каталог удаляются после завершения команды — и при ошибке, и при ненулевом коде, и при прерывании: Ctrl-C команда получает от терминала, SIGTERM и SIGHUP пересылаются ей. От принудительного завершения (`kill -9`) защиты нет: тогда каталог останется во временном каталоге пользователя.
- Код завершения — код команды (при завершении сигналом — `128 + номер сигнала`).

## serve

Запускает MCP-сервер через stdio. stdout занят протоколом MCP, логи и ошибки запуска — только в stderr.

```
appstore-connect-mcp serve [--profile <имя>] [--allow-write] [--allow-destructive]
    [--toolsets <набор,...>|all] [--dynamic-toolsets] [--tools-file <путь>]...
    [--allow-path <каталог>]... [--timeout <секунды>] [--max-response-bytes <байты>]
    [--log-level <уровень>] [--status]
```

- Ключ берётся только из профиля: `.p8` из системного хранилища, Key ID и Issuer ID из `profiles.toml`. JWT подписывается при первом запросе к API, поэтому запуск, `initialize` и `tools/list` обходятся без сети. Нет ключа или хранилище недоступно — сервер не запускается: ненулевой код выхода, сообщение в stderr, в stdout ничего.
- Права — из профиля ([Профили](#профили)): уровень доступа и каталоги `allow_path`; без них — только чтение. Флаги `--allow-write`, `--allow-destructive` и `--allow-path` права только сужают: флаг, который просит больше, чем разрешено в профиле, — ошибка запуска с подсказкой. На macOS права сверх одобренных отсекаются с предупреждением в stderr, сервер при этом запускается. Инструменты выше уровня не регистрируются вовсе; вызов такого инструмента объясняет, как поднять уровень. Аннотации `readOnlyHint`/`destructiveHint` соответствуют уровню.
- Наборы инструментов: `--toolsets` через запятую или `all`. По умолчанию — `apps,versions-review,builds,testflight`. Неизвестный набор — ошибка запуска со списком допустимых. Список наборов с числом инструментов — `appstore-connect-mcp toolsets`.
- `--dynamic-toolsets` (или `dynamic_toolsets = true` в профиле) — наборы по запросу агента, см. ниже.
- `--tools-file` — дополнительный файл пользовательских инструментов (повторяемый), см. [tools](#tools).
- `--toolsets` важнее настройки профиля `toolsets`; без флага действует профиль. Динамические наборы включаются, если задан `--dynamic-toolsets` или `dynamic_toolsets = true` в профиле.
- Каталоги для файлов: рабочий каталог сервера (если это не корень файловой системы и не домашний каталог), системный временный каталог и каталоги `allow_path` профиля. `--allow-path` (повторяемый) оставляет из них только указанный каталог, который должен лежать внутри каталога профиля. Существующие файлы не перезаписываются ([Локальные файлы](security.md#локальные-файлы)).
- `--timeout` — таймаут одного запроса к API (по умолчанию 60 с; для адресов загрузки и скачивания файлов — не меньше 300 с). `--max-response-bytes` — лимит текста результата для агента (по умолчанию 256 КиБ): больший ответ — ошибка с подсказкой сузить запрос.
- `--log-level` — уровень или фильтр логов в stderr, например `info` или `appstore_connect_mcp_core=debug`; без него — `RUST_LOG`, иначе `warn`.
- `--status` печатает профиль, наличие ключа (без значения), Key ID, Issuer ID, уровень доступа и состояние одобрения (macOS), наборы, режим динамических наборов, число инструментов, пользовательские инструменты (сколько определено и сколько зарегистрировано) и разрешённые каталоги, и выходит без запуска сервера и без запросов к API. Если профиль не готов (нет ключа, Key ID или Issuer ID), `--status` говорит об этом последней строкой.

Аргументы инструментов операций — параметры пути и запроса с точкой вместо скобок JSON:API (`filter.bundleId` → `filter[bundleId]`, `fields.apps` → `fields[apps]`, `limit.builds` → `limit[builds]`); массивы (`include`, `fields.*`, `filter.*`) передаются JSON-массивами и уходят в запрос через запятую. Тело запроса — аргумент `body` (JSON-объект). Неизвестные, недостающие и неверные по типу или `enum` аргументы отклоняются до запроса. У операций с `include` есть аргумент `flatten: true`: связанные ресурсы из `included` подставляются на место ссылок `{type, id}`, атрибуты поднимаются на уровень ресурса, `included` и `links` убираются. У операций с двоичным ответом (отчёты продаж и финансов) обязателен `save_to`.

Ответ — документ JSON:API как есть. Если есть следующая страница или общее число записей, ответ оборачивается: `{"result": <ответ>, "pagination": {"next": <URL>, "total": <число>, "limit": <размер страницы>}}`; когда часовая квота запросов почти исчерпана (меньше 10 %), добавляется `"rate_limit": {"remaining", "limit"}`. Ошибки API возвращаются результатом с `isError: true`: статус, ошибки JSON:API (`code`, `detail`, `source`) и подсказка.

Наборы, уровни доступа, составные инструменты и промпты — в [MCP-инструментах](tools.md).

### api_search и api_request

Эти два инструмента регистрируются всегда, независимо от `--toolsets`.

- `api_search` ищет по всем операциям API без обращения к нему: инструменты операций, операции без своего инструмента (устаревшие, чтение связей `relationships`, дубли списков) и составные инструменты. Слова — на английском или русском: русские термины App Store Connect переводятся словарём («приложение» → app, «сборка» → build, «тестировщик» → tester, «скриншот» → screenshot, «подписка» → subscription, «цена» → price, «сертификат» → certificate, «отчёт» → report и т. д.). Каждый результат говорит, можно ли вызвать операцию на этом сервере, а если нет — почему и что её включает (флаг доступа, набор, вызов через `api_request`). Аргументы: `query`, `toolset` (искать в одном наборе), `limit` (по умолчанию 15). С аргументом `tool_name` возвращает полное описание и схему аргументов одного инструмента.
- `api_request` вызывает любой путь API в пределах уровня доступа сервера: относительный путь `/v1/…` (`/v2/…`, `/v3/…`; query — после `?` или объектом `query`, имена с точкой переводятся в запись со скобками) либо полный адрес `links.next` следующей страницы с хоста API (только `GET`). Другие полные адреса, `..`, `//` отклоняются; заголовков инструмент не принимает, `Authorization` добавляет сервер. Уровень доступа берётся у операции, которой соответствует путь (в том числе у операций без инструмента; регистр букв и percent-кодирование уровень не понижают), для неизвестного пути — по методу: `GET` — чтение, `DELETE` — удаление, остальные — запись. Метод — `method` (`GET` по умолчанию, `POST`, `PATCH`, `PUT`, `DELETE`). Тело — `body` или `body_file` (локальный JSON-файл). `save_to` сохраняет ответ в новый файл; для двоичных ответов (отчёты продаж и финансов) он обязателен.

### Фильтр jq

Инструменты операций с JSON-ответом, составные и пользовательские инструменты и `api_request` принимают необязательный аргумент `jq` — фильтр в диалекте [jaq](https://github.com/01mf02/jaq), например `[.data[] | {id, name: .attributes.name}]`. Фильтр применяется к телу ответа после `flatten`; постраничная выдача остаётся снаружи: `{"result": <результат фильтра>, "pagination": {...}}`. Лимит `--max-response-bytes` действует на результат фильтра, поэтому большой ответ можно сузить фильтром. Несколько результатов возвращаются массивом, ни одного — `[]`.

- Синтаксис и имена проверяются до запроса к API: сломанный фильтр не оставляет выполненной записи без ответа.
- Ошибка выполнения фильтра после изменяющего запроса прямо говорит, что запрос выполнен и повторять его не нужно.
- Фильтру недоступны окружение (`env`, `$ENV`), файлы, `input`/`inputs` и вывод в stderr. `serve` выполняет фильтры в дочернем процессе того же бинарника (скрытая подкоманда `jq-worker`) с пустым окружением и таймаутом 10 с: зацикливание или переполнение стека завершают только этот процесс.
- С `save_to` фильтр не сочетается; у операций с двоичным ответом аргумента `jq` нет.

### Динамические наборы

С `--dynamic-toolsets` сервер при запуске регистрирует только `api_search`, `api_request`, `list_toolsets`, `enable_toolset`, `disable_toolset`, наборы из `--toolsets` (без него — ни одного) и пользовательские инструменты. Агент смотрит наборы (`list_toolsets`: описание, число инструментов на уровне доступа сервера, примеры имён, включён ли набор) и включает нужные (`enable_toolset` с `toolset: "testflight"` или списком через запятую); сервер отправляет `notifications/tools/list_changed` (в сессии протокола 2026-07-28 — через подписку `subscriptions/listen`). Уровень доступа действует как обычно: включение набора не регистрирует инструменты выше него. Режим нужен клиентам, которые сразу кладут в контекст описания всех инструментов.

### Секреты и большие данные в ответах

Агент не видит учётных данных ([Безопасность](security.md#секреты-в-ответах)): во всех ответах, включая ошибки и результаты составных инструментов, они заменяются на `"[redacted]"`, а обёртка ответа получает поле `note` с пояснением (у текстовых ответов и ошибок пояснение дописывается в конец).

- Поля по имени на любой глубине: пароли, токены, ключи, `Authorization` (имя приводится к snake_case: `demoAccountPassword`, `p12Password`, `secret` вебхука). Признаки (`is…`, `has…`) и пустые строки не трогаются.
- Значения по форме в любом тексте: JWT, `Bearer …`/`Basic …`, блоки закрытых ключей PEM, пароли в URL (`https://user:пароль@host`), параметры подписи в URL (`X-Amz-Signature`, `X-Amz-Credential`, `Signature`, `sig`, `token` и т. п.). Адреса следующей страницы (`links.next`) не меняются.
- Адреса загрузки `uploadOperations[].url` и значения `requestHeaders` (кроме `Content-Type` и подобных) скрываются: файлы загружают `asset_upload` и `build_upload`. Адреса скачивания сегментов аналитических отчётов (`analyticsReportSegments`, `url`) скрываются: отчёты скачивает `report_download`.
- Большое base64-содержимое `certificateContent` и `profileContent` (длиннее 64 символов) в ответе заменяется пояснением: профиль скачивает `profile_download`, полный ответ сохраняет `api_request` с `save_to`. В файле `save_to` содержимое остаётся, учётные данные вырезаются так же.
- Порядок обработки: вырезание → `flatten` → `jq` → обёртка → лимит размера. Фильтр получает уже очищенный ответ и не может раскрыть скрытые значения.
- JWT, выпущенные сервером, дополнительно вырезаются из любого итогового текста; в логи (stderr) ключ и JWT не пишутся.

## call

Вызывает инструмент сервера из консоли.

```
appstore-connect-mcp call [--profile <имя>] [--allow-write] [--allow-destructive]
    [--allow-path <каталог>]... [--toolsets <набор,...>] [--tools-file <путь>]...
    [--timeout <секунды>] [--max-response-bytes <байты>]
    [<инструмент> [<имя>=<значение> | <имя>:=<JSON>]... [--args <JSON>|-] [--schema] [--yes] [--raw]]
```

- Без инструмента печатает инструменты, доступные профилю, с уровнем доступа и первой строкой описания. `--schema` печатает схему аргументов инструмента.
- Сервер собирается как в `serve` без флагов: права профиля (на macOS — одобренные), флаги только сужают. По умолчанию включены все наборы (`--toolsets` сужает), наборов по запросу нет. Клиент MCP работает в этом же процессе, поэтому проверка аргументов, уровни доступа, фильтр `jq` и вырезание секретов те же, что у агента.
- Аргументы: `имя=значение` — тип берётся из схемы инструмента (числа, логические значения, JSON-массивы и объекты; для массива строк — список через запятую), `имя:=JSON` — всегда JSON, `--args` — все аргументы одним JSON-объектом (`-` — из stdin). Флаги команды пишутся до имени инструмента.
- Инструменты уровня удаления спрашивают подтверждение в терминале; `--yes` — без вопроса, без терминала вызов отклоняется.
- Результат: текстовые блоки (JSON — с отступами); `--raw` — ответ MCP целиком. Код выхода — 0, если инструмент выполнился, и 1, если он вернул ошибку (`isError`) или вызов не удался.

```bash
appstore-connect-mcp call list_apps fields.apps=name,bundleId limit=5
appstore-connect-mcp call api_request path=/v1/apps jq='[.data[].attributes.name]'
appstore-connect-mcp call --profile client list_builds --args '{"filter.app": ["1234567890"]}'
```

## ui

Интерактивный просмотр профилей в терминале.

```
appstore-connect-mcp ui
```

Вкладки:

- **Profile** — настройки профиля и состояние ключа: есть ли ключ в хранилище (сам ключ не показывается), Key ID, тип ключа, номер поставщика, наборы.
- **Access** — права профиля и их одобрение. `r`, `w`, `d` — уровень, `a` — добавить каталог, `x` — убрать, `u` — отменить, `s` — сохранить. На macOS сохранение прав шире одобренных спрашивает Touch ID или пароль пользователя macOS.
- **Clients** — регистрации сервера в Claude Code (`~/.claude.json`, `.mcp.json` текущего каталога) и Codex (`$CODEX_HOME/config.toml`): профиль, флаги и расхождения с правами профиля. `f` регистрирует запись заново без флагов доступа. Значения переменных окружения записей не читаются.
- **Account** — что видно ключу в App Store Connect (`c` — проверить): число приложений, доступ к пользователям (нужна роль Admin) и сертификатам. Роль ключа App Store Connect ключу не сообщает: её видно в Users and Access > Integrations.
- **Tools** — инструменты, которые профиль даёт агенту (`c` — загрузить), `Enter` — вызвать с аргументами `имя=значение`, `?` — схема.

`q` или `Esc` — выход, `Tab` и `1`–`5` — вкладки, `F5` — перечитать. Без терминала (агент, CI) команда завершается ошибкой.

## toolsets

```
appstore-connect-mcp toolsets
```

Печатает наборы инструментов: `TOOLSET`, число инструментов уровней чтения (`READ`), записи (`WRITE`) и удаления (`DESTRUCTIVE`), `DEFAULT` (входит ли в набор по умолчанию) и описание, в конце — итог. Считаются инструменты операций и составные инструменты; `api_search` и `api_request` в наборы не входят. Сервер только для чтения регистрирует инструменты `READ` своих наборов, `--allow-write` добавляет `WRITE`, `--allow-destructive` — `DESTRUCTIVE`. Профиль, ключ и сеть не нужны.

## tools

```
appstore-connect-mcp tools list [--tools-file <путь>]...
appstore-connect-mcp tools check [--tools-file <путь>]...
```

Пользовательские инструменты — операции API с фиксированными аргументами и фильтром. Файл пользователя `~/.config/appstore-connect-mcp/tools.toml` (рядом с `profiles.toml`) читается всегда, если он есть; другие файлы, например из репозитория проекта, — только по явному `--tools-file` у `serve` и у этих команд: файл из чужого репозитория не должен молча добавлять инструменты.

```toml
[[tools]]
name = "recent_builds"
description = "Latest builds of the main app"
operation = "list_builds"
jq = "[.data[] | {id, version: .attributes.version}]"

[tools.args]
"filter.app" = ["1234567890"]
sort = ["-uploadedDate"]
limit = 10
```

- `operation` — имя инструмента операции (см. `api_search` или `toolsets`); уровень доступа инструмента — уровень операции. Инструмент выше уровня сервера не регистрируется, вызов объясняет, какой флаг нужен; наборы его не ограничивают.
- `args` — фиксированные аргументы с теми же именами, что у инструмента операции. Они проверяются при загрузке (имя, тип, `enum`), убираются из схемы, а переданный агентом фиксированный аргумент — ошибка. `save_to` фиксировать нельзя.
- `jq` — фильтр ответа; фильтр из вызова агента применяется к его результату.
- Имя — строчные латинские буквы, цифры и `_`, до 40 символов; не совпадает со встроенными инструментами (всеми операциями, а не только включёнными, `api_*`, инструментами динамических наборов, составными) и с другими пользовательскими.

`tools list` печатает инструменты (имя, уровень доступа, операция, фиксированные аргументы, файл), `tools check` — проверенные файлы и число инструментов в каждом. Ошибка в файле (неизвестный ключ, операция, аргумент или сломанный фильтр) — ненулевой код выхода с именем файла и инструмента; `serve` с такой ошибкой не запускается.
