# Подключение к MCP-клиентам

Сервер работает через stdio: MCP-клиент сам запускает `appstore-connect-mcp serve --profile <профиль>` и общается с ним через stdin и stdout. Ключ API сервер берёт из системного хранилища по имени профиля, поэтому в конфигурации клиента ключа нет. HTTP-режима нет: серверу пришлось бы принимать `.p8` в каждом запросе ([Безопасность](security.md#почему-нет-http-режима)).

Один профиль — один кабинет App Store Connect. Для нескольких кабинетов подключите несколько серверов с разными профилями ([Профили и несколько кабинетов](api-key.md#профили-и-несколько-кабинетов)).

## Claude Code и Codex: connect

```bash
appstore-connect-mcp connect claude-code
appstore-connect-mcp connect codex
```

`connect` по шагам:

1. Если у профиля уже есть ключ в хранилище и он проходит проверку `GET /v1/apps?limit=1`, использует его без вопросов.
2. Иначе открывает в браузере страницу ключей App Store Connect, подсказывает, как создать командный ключ ([Ключ App Store Connect API](api-key.md)), и спрашивает путь к `.p8`, Key ID и Issuer ID. По SSH, без графической сессии и с `--no-browser` ссылка только печатается. Без терминала ключ можно передать только через `--key-file`.
3. Проверяет ключ и сохраняет его в системное хранилище, а настройки — в профиль `~/.config/appstore-connect-mcp/profiles.toml`.
4. Показывает, что изменится в конфигурации клиента, и после подтверждения регистрирует сервер: в Claude Code — через `claude mcp add`, в Codex — таблицей `[mcp_servers.<имя>]` в `$CODEX_HOME/config.toml` (по умолчанию `~/.codex/config.toml`; комментарии и форматирование файла сохраняются).
5. Если ключ читался из файла, один раз предлагает удалить этот файл (по умолчанию — нет).

После этого перезапустите клиент. Все флаги — в [справочнике CLI](cli.md#connect).

В клиент записывается только команда запуска, например:

```
/opt/homebrew/bin/appstore-connect-mcp serve --profile default --dynamic-toolsets
```

Путь — абсолютный путь бинарника, из которого запущен `connect`; дальше — профиль и флаги доступа. Ключа, Key ID, Issuer ID и переменных окружения в записи нет.

### Права и наборы

Флаги `connect` сохраняются в профиль и попадают в команду запуска сервера:

```bash
# Только чтение (по умолчанию)
appstore-connect-mcp connect codex

# Создание и изменение данных
appstore-connect-mcp connect codex --allow-write

# Плюс удаление и действия с последствиями для покупателей (отправка на проверку, выпуск, цены)
appstore-connect-mcp connect codex --allow-destructive

# Наборы, включённые при запуске
appstore-connect-mcp connect claude-code --toolsets apps,versions-review,metadata,media
```

По умолчанию `connect` регистрирует сервер с `--dynamic-toolsets`: при запуске у агента только инструменты поиска и управления наборами (и наборы из `--toolsets`), а нужные разделы он включает сам. `--no-dynamic-toolsets` регистрирует сервер со всеми инструментами включённых наборов сразу ([Динамические наборы](tools.md#динамические-наборы)).

Чтобы поменять права, запустите `connect` ещё раз с нужными флагами: сохранённый ключ остаётся, а флаги доступа и наборы в профиле и в записи клиента перезаписываются. Запись с тем же профилем `connect` заменяет после подтверждения (или сразу с `--yes`).

С `--scope project` (только Claude Code) сервер регистрируется в `.mcp.json` текущего каталога. Ключ остаётся в хранилище того, кто запускал `connect`, а в команде записан абсолютный путь к бинарнику на его машине: другим участникам проекта нужен свой ключ под тем же именем профиля (`appstore-connect-mcp auth login --profile <профиль>`) и бинарник по тому же пути.

## Имя сервера

| Профиль | Имя сервера в клиенте |
| --- | --- |
| `default` | `appstore-connect` |
| любой другой, например `client` | `asc-client` (точки в имени профиля заменяются на `-`) |
| явно | `--name <имя>` |

Имя короткое из-за ограничения клиентов: они называют инструменты `mcp__<сервер>__<инструмент>` и ограничивают это имя 64 символами, а имена инструментов сервера бывают длиной до 40 символов. Значит, имя сервера должно быть не длиннее 17 символов (64 − 40 − 5 − 2): `appstore-connect` — 16, `asc-` и до 13 символов профиля. Для более длинного имени `connect` предупреждает: часть инструментов клиент может укоротить или отклонить. Выбирайте короткие имена профилей.

Запись с тем же именем, которая запускает другой сервер или `appstore-connect-mcp` с другим профилем, `connect` заменяет только после явного ответа в терминале; `--yes` её не трогает. Так `appstore-connect-mcp` можно подключить рядом с другим MCP-сервером App Store Connect под другим именем (`--name`).

## Другие клиенты: ручное подключение

`connect` настраивает только Claude Code и Codex. Любой клиент, который запускает stdio MCP-серверы, подключается вручную:

1. Сохраните ключ в профиль:

   ```bash
   appstore-connect-mcp auth login --profile cursor --key-file ~/Downloads/AuthKey_ABC123DEFG.p8 \
       --issuer-id 00000000-0000-0000-0000-000000000000
   ```

2. Узнайте абсолютный путь к бинарнику: `command -v appstore-connect-mcp`. Клиенты, запущенные не из терминала, часто не видят `PATH` оболочки.

3. Зарегистрируйте в клиенте stdio-сервер: команда — путь к `appstore-connect-mcp`, аргументы — `serve --profile <профиль>` и нужные флаги. Формат `mcpServers`, который понимает большинство клиентов:

   ```json
   {
     "mcpServers": {
       "asc-cursor": {
         "command": "/opt/homebrew/bin/appstore-connect-mcp",
         "args": ["serve", "--profile", "cursor", "--allow-write"]
       }
     }
   }
   ```

   Переменные окружения и ключ в записи не нужны. Если клиент кладёт в контекст описания всех инструментов сразу и поддерживает `notifications/tools/list_changed`, добавьте `"--dynamic-toolsets"`.

4. Перезапустите клиент и проверьте, что у сервера появились инструменты.

Если флаги доступа и `--toolsets` в `args` не указаны, сервер берёт их из настроек профиля, а без настроек работает только на чтение с наборами по умолчанию. Проверить, с какими настройками запустится сервер:

```bash
appstore-connect-mcp serve --status --profile cursor
```

### Ручная регистрация в Claude Code и Codex

Если вы не хотите, чтобы `connect` менял конфигурацию, зарегистрируйте сервер сами после `auth login`:

```bash
claude mcp add --scope user appstore-connect -- "$(command -v appstore-connect-mcp)" serve --profile default
```

```toml
# ~/.codex/config.toml
[mcp_servers.appstore-connect]
command = "/opt/homebrew/bin/appstore-connect-mcp"
args = ["serve", "--profile", "default"]
```

## Рабочий каталог и локальные файлы

Инструменты, которые читают или сохраняют файлы (загрузка скриншотов и сборок, отчёты, метаданные, сертификаты и профили), работают только с путями внутри рабочего каталога сервера, системного временного каталога и каталогов из `--allow-path`. Рабочий каталог сервера — тот, в котором клиент его запустил (обычно каталог проекта). Если клиент запускает сервер в домашнем каталоге или в корне файловой системы, рабочий каталог в разрешённые не попадает: добавьте нужные каталоги через `--allow-path` в аргументы сервера. Подробнее — [Безопасность](security.md#локальные-файлы).

## Проверка профиля

```bash
appstore-connect-mcp auth status --profile client
```

Команда показывает Key ID, тип ключа, есть ли ключ в хранилище (не его значение), vendor number, настройки доступа и результат проверочного запроса к API.

## Отключение

1. Удалите запись из клиента: `claude mcp remove --scope user appstore-connect` (или `asc-<профиль>`), таблицу `[mcp_servers.<имя>]` из `~/.codex/config.toml` или запись из конфигурации другого клиента.
2. Удалите ключ из хранилища и настройки профиля: `appstore-connect-mcp auth logout --profile <профиль> --forget`.
3. Если ключ больше нигде не нужен, отзовите его в App Store Connect ([Отзыв ключа](api-key.md#отзыв-ключа)).
