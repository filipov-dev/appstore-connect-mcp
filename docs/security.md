# Безопасность

Сервер даёт агенту доступ к кабинету App Store Connect от имени ключа API. Ниже — какие границы держит сам сервер и что остаётся на стороне пользователя.

## От чего защищает сервер

- **Утечка ключа через агента.** Агент не получает ключ `.p8` и JWT ни в одном ответе, ошибке или логе и не может передать их в аргументах инструментов.
- **Случайные изменения.** По умолчанию сервер только читает; запись и действия, которые видят покупатели, включает пользователь флагами.
- **Секреты из данных кабинета.** Пароли демо-аккаунтов для App Review, временные ссылки загрузки, подписанные адреса отчётов и похожие значения вырезаются из ответов.
- **Произвольный доступ к сети и файлам.** `api_request` ходит только в App Store Connect API; локальные файлы — только в разрешённых каталогах, существующие файлы не перезаписываются.

От чего сервер не защищает: от агента с доступом к оболочке на той же машине, который запускает команды от имени пользователя (он может, например, вызвать `appstore-connect-mcp key exec`), и от ключа с ролью шире, чем нужно. Граница прав в кабинете — [роль ключа](api-key.md#роли); флаги доступа сервера сужают то, что агент делает через MCP.

## Ключ API и JWT

- Ключ хранится только в системном хранилище: macOS Keychain, Secret Service в Linux. Запись: сервис `dev.filipov.appstore-connect-mcp`, учётная запись — имя профиля. Запасного файлового хранилища нет.
- Ключ принимается только файлом (`--key-file`, не больше 16 КиБ) или путём, введённым в терминале. Он не принимается содержимым в аргументе командной строки и не читается из переменных окружения или `.env`.
- Ни одна команда не печатает ключ: `auth status` и `serve --status` показывают только, сохранён ли он. Команды, которая выводит ключ, нет.
- В конфигурацию MCP-клиента попадает только команда `appstore-connect-mcp serve --profile <профиль> …`, в `profiles.toml` — Key ID, Issuer ID и настройки без ключа.
- JWT (ES256, срок 15 минут, замена за 5 минут до истечения) выпускается в памяти процесса сервера при первом запросе к API и никуда не записывается. Память с ключом и JWT затирается после использования, в отладочном выводе они скрыты.
- Заголовок `Authorization` добавляет только сервер; `api_request` не принимает заголовков и не может его переопределить. Запросы с JWT уходят только на `https://api.appstoreconnect.apple.com`; редиректы на другие хосты не выполняются.
- Один профиль — один кабинет и один ключ. Ключ любого агента или машины можно отозвать в App Store Connect, не трогая остальных ([Отзыв ключа](api-key.md#отзыв-ключа)).

### key exec

Некоторым программам (`xcrun altool`, `xcrun notarytool`, fastlane) нужен файл `.p8`. `appstore-connect-mcp key exec -- <команда>` отдаёт ключ дочерней команде, не показывая его:

- ключ пишется в новый файл `AuthKey_<KEYID>.p8` с правами 0600 в новом временном каталоге с правами 0700; в окружение команды попадают путь к файлу, Key ID и Issuer ID, но не содержимое ключа;
- команда запускается без оболочки, её stdout и stderr проходят через маскировщик: ключ целиком, по строкам и в base64 заменяется на `***`. Это страховка от случайного вывода, а не граница безопасности;
- файл и каталог удаляются после завершения команды при любом исходе, в том числе при Ctrl-C, SIGTERM и SIGHUP. От `kill -9` защиты нет: тогда каталог останется во временном каталоге пользователя.

Подробнее — [справочник CLI](cli.md#key-exec).

### Секреты составных инструментов

`certificate_create` генерирует приватный ключ сертификата и, при необходимости, пароль `.p12`. Они сохраняются в системное хранилище под отдельным сервисом `dev.filipov.appstore-connect-mcp.secrets` (записи `<профиль>/certificate/<id>/private-key` и `<профиль>/certificate/<id>/p12-password`), а агент получает только имена записей. Пароль, который пользователь задаёт сам, передаётся файлом (`p12_password_file`), а не в аргументах, и не сохраняется. Файл `.p12` создаётся с правами 0600.

## Уровни доступа

- По умолчанию сервер работает только на чтение. `--allow-write` включает создание и изменение, `--allow-destructive` (включает и запись) — удаление и действия с последствиями для пользователей App Store: отправку на проверку, выпуск версии и поэтапный релиз, цены, доступность по странам и предзаказы, деактивацию и отзыв сертификатов, пользователей и роли, приглашения тестировщиков, публичные ответы на отзывы. Удаление связи между ресурсами — уровень записи. Полный список — в [MCP-инструментах](tools.md#уровни-доступа).
- Инструменты выше разрешённого уровня не регистрируются: агент их не видит. Вызов по имени возвращает ошибку с флагом, который их включает.
- У каждого инструмента есть аннотации `readOnlyHint` и `destructiveHint` по уровню.
- `api_request` проверяет уровень операции, которой соответствует путь (в том числе операций без своего инструмента; регистр букв и percent-кодирование уровень не понижают), для неизвестного пути — по методу: `GET` — чтение, `DELETE` — удаление, остальные — запись.
- `metadata_apply` удаляет локализации (`delete_missing_locales`) только на сервере с `--allow-destructive`, хотя сам инструмент — уровня записи.

Инструкции сервера просят агента подтверждать с пользователем отправку на проверку, выпуск и другие действия с последствиями, если о них не просили явно, а промпты выполняют такие шаги только после подтверждения.

## Секреты в ответах

Во всех ответах агенту, включая ошибки и результаты составных инструментов, сервер заменяет на `"[redacted]"`:

- поля паролей, токенов и ключей по имени на любой глубине (имя приводится к snake_case: `demoAccountPassword`, `p12Password`, `secret` вебхука и т. п.);
- значения по форме в любом тексте: JWT, `Bearer …`/`Basic …`, блоки закрытых ключей PEM, пароли в URL (`https://user:пароль@host`), параметры подписи в URL (`X-Amz-Signature`, `Signature`, `token` и т. п.);
- адреса и заголовки загрузки `uploadOperations[].url` и `requestHeaders` — файлы загружают `asset_upload` и `build_upload`; адреса сегментов аналитических отчётов — отчёты скачивает `report_download`.

Большое base64-содержимое `certificateContent` и `profileContent` в ответ не отдаётся: его можно сохранить в файл (`profile_download`, `api_request` с `save_to`). JWT, выпущенные сервером, дополнительно вырезаются из любого итогового текста. Когда что-то вырезано, ответ получает поле `note` с пояснением. Фильтр `jq` получает уже очищенный ответ и не может раскрыть скрытые значения. Подробный список — в [справочнике CLI](cli.md#секреты-и-большие-данные-в-ответах).

Временные адреса, которые выдаёт API (части загрузки, сегменты отчётов), вызываются отдельным клиентом: только https, без заголовка `Authorization` и без редиректов; адрес не попадает ни в ответ, ни в текст ошибки.

## Фильтр jq

Фильтр выполняется в отдельном процессе того же бинарника с пустым окружением и таймаутом 10 секунд: ему недоступны переменные окружения, файлы, хранилище ключей и сеть, а зависание или переполнение стека завершают только этот процесс. Синтаксис фильтра проверяется до запроса к API.

## Пользовательские инструменты

Файлы пользовательских инструментов — доверенная конфигурация пользователя. Автоматически читается только `~/.config/appstore-connect-mcp/tools.toml`; другие файлы (например, из репозитория проекта) — только явным `--tools-file`. Пользовательский инструмент вызывает обычную операцию API через те же проверки: схема аргументов, уровень доступа операции, вырезание секретов. Фиксированные аргументы агент переопределить не может, `save_to` фиксировать нельзя, имя, совпадающее со встроенным инструментом, — ошибка запуска.

## Локальные файлы

Аргументы с путями (`file` у инструментов загрузки, `save_to` у скачивания, `dir` у метаданных, `body_file` у `api_request`, `p12_password_file`) работают только с путями внутри разрешённых каталогов:

- рабочий каталог сервера, если это не корень файловой системы и не домашний каталог;
- системный временный каталог: он разрешён для черновых файлов и скачиваний, но общий для всех программ пользователя, поэтому не держите в нём ничего личного;
- каталоги из `--allow-path` (флаг повторяемый).

Пути проверяются после раскрытия `..` и символических ссылок: ссылка, которая ведёт за пределы разрешённых каталогов, отклоняется. Относительный путь считается от рабочего каталога сервера. Существующие файлы никогда не перезаписываются: для скачивания нужен новый файл.

Единственное исключение — `profile_download` с `install: true` на macOS: копия профиля кладётся в каталог Xcode `~/Library/Developer/Xcode/UserData/Provisioning Profiles/` под именем `<UUID>`, где UUID проверяется по формату, а другой файл с тем же именем не перезаписывается.

Разрешённые каталоги показывает `appstore-connect-mcp serve --status` (строка `Files`).

## Протокол и логи

- stdout занят протоколом MCP; логи и диагностика пишутся только в stderr. Уровень — `--log-level`, иначе `RUST_LOG`, иначе `warn`. Ключ и JWT в логи не попадают.
- Ошибки App Store Connect (`4xx`, `5xx`) и запрещённые вызовы возвращаются агенту как результат инструмента с `isError: true`; процесс не падает.
- Сервер не открывает сетевых портов и ходит только в App Store Connect API и на временные адреса, которые выдаёт API.

## Почему нет HTTP-режима

Сервер работает только через stdio. В HTTP-режиме ключ `.p8` пришлось бы передавать серверу в каждом запросе, то есть хранить его в конфигурации MCP-клиента, где его видит агент. Ключ App Store Connect — долгоживущий и с широкими правами, поэтому он остаётся в системном хранилище машины, на которой работает агент.
