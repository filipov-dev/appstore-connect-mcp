# MCP-инструменты

Каждая операция App Store Connect API из встроенного снимка спецификации Apple — отдельный MCP-инструмент. Поверх операций есть восемь [составных инструментов](#составные-инструменты), которые выполняют многошаговые сценарии за один вызов, и три [промпта](#промпты). Всегда доступны `api_search` и `api_request`.

Какие инструменты видит агент, задают уровень доступа (`--allow-write`, `--allow-destructive`) и наборы (`--toolsets`) сервера. Со значениями по умолчанию — только чтение и четыре набора — это 124 инструмента (включая `api_search` и `api_request`); с `--allow-write` — 165, с `--allow-destructive` — 194. Со всеми наборами (`--toolsets all`): 490, 770 и 913. Посмотреть число инструментов для своих настроек: `appstore-connect-mcp serve --status`.

## Уровни доступа

По умолчанию сервер работает только на чтение. Инструменты выше разрешённого уровня не регистрируются: агент их не видит, а вызов по имени возвращает ошибку с флагом, который их включает.

| Уровень | Как включить | Инструменты |
| --- | --- | --- |
| read-only | по умолчанию | только чтение |
| write | `--allow-write` | плюс создание и изменение (`POST`, `PATCH`), удаление связей между ресурсами |
| destructive | `--allow-destructive` (включает запись) | плюс удаление (`DELETE`) и действия с последствиями для пользователей App Store |

Уровень операции по умолчанию — по методу: `GET` — чтение, `POST` и `PATCH` — запись, `DELETE` — удаление. Удаление связи (`DELETE …/relationships/…`, инструменты `remove_…`) — уровень записи: связанный ресурс не удаляется.

Уровень удаления, кроме `DELETE`, получают действия, последствия которых сразу видят покупатели, люди вне команды, или которые нельзя отменить:

| Действие | Примеры инструментов |
| --- | --- |
| Отправка на проверку App Review и бета-проверку TestFlight, изменение и отмена отправки | `create_review_submission`, `create_review_submission_item`, `update_review_submission`, `create_beta_app_review_submission`, отправка покупок и подписок |
| Выпуск версии, поэтапный релиз, продвижение варианта эксперимента | `create_app_store_version_release_request`, `create_app_store_version_phased_release`, `update_app_store_version_phased_release`, `create_app_store_version_promotion` |
| Цены приложения, покупок и подписок | расписания цен, цены подписок, отмена запланированных цен |
| Доступность по странам и предзаказы | доступность приложения, покупок и подписок, завершение предзаказов |
| Деактивация сертификата | изменение сертификата (`activated: false`); удаление (отзыв) — `DELETE` и так уровня удаления |
| Пользователи команды, их роли и доступ к приложениям, приглашения | изменение пользователя и его ролей, видимые приложения, приглашения (просмотр `list_users` — чтение) |
| Приглашения и уведомления тестировщиков TestFlight | `create_beta_tester`, `create_beta_tester_invitation`, `add_beta_tester_groups`, `add_beta_tester_builds`, добавление тестировщиков в группу и к сборке, уведомления о сборке |
| Публичные ответы на отзывы | `create_customer_review_response` |
| Необратимые изменения | `update_build` (через него сборку можно сделать истёкшей, а это не отменяется), удаление вводных предложений подписки |
| Данные, которые видят игроки Game Center | результаты и достижения игроков, модерация результатов, блокировка игроков |

И одно исключение в обратную сторону: проверка набора правил матчмейкинга Game Center на тестовых запросах (`POST`) ничего не сохраняет и доступна на уровне чтения. Причина повышенного уровня попадает в описание инструмента («Destructive: …»), поэтому агент видит её.

У каждого инструмента есть аннотации MCP `readOnlyHint` и `destructiveHint`, соответствующие его уровню. Флаги командной строки важнее настроек профиля ([`serve`](cli.md#serve)). Уровень доступа сервера не расширяет права ключа: App Store Connect всё равно проверяет роль ключа ([Роли](api-key.md#роли)).

### Динамические наборы

Клиенты, которые не откладывают загрузку инструментов, кладут описания всех зарегистрированных инструментов в контекст модели сразу. С `serve --dynamic-toolsets` (или `dynamic_toolsets = true` в профиле; `connect` включает это по умолчанию) сервер при запуске регистрирует только:

- `api_search` и `api_request`;
- `list_toolsets` — наборы с описанием, числом инструментов на уровне доступа сервера, примерами имён и признаком, включён ли набор;
- `enable_toolset` — включить набор (аргумент `toolset`, можно несколько через запятую);
- `disable_toolset` — выключить набор;
- наборы из `--toolsets` (без него — ни одного) и [пользовательские инструменты](#пользовательские-инструменты).

После `enable_toolset` и `disable_toolset` сервер отправляет клиенту `notifications/tools/list_changed`. Уровень доступа действует как обычно: включение набора не регистрирует инструменты выше него. Если клиент не перечитывает список инструментов, агент может вызвать ту же операцию через `api_request`.

## Имена и исключённые операции

Имя инструмента — `глагол_ресурс` в snake_case из `operationId` спецификации: `list_apps`, `get_app`, `create_app_store_version`, `list_app_store_versions`; запись связей «ко многим» — `add_…`, `remove_…`, `replace_…`, связи «к одному» — `set_…` (`set_app_store_version_build`). Имена не длиннее 40 символов: длинные сокращаются (`loc` — localization, `gc` — Game Center, `iap` — in-app purchase и т. п.).

Своего инструмента нет у трёх видов операций:

- устаревших (`deprecated` в спецификации Apple);
- чтения одних идентификаторов связей (`GET …/relationships/…`): тот же список с атрибутами отдаёт обычная операция связанных ресурсов;
- дублей списков связанных ресурсов, которые покрывает список верхнего уровня с фильтром.

`api_search` находит и их: результат говорит, чем заменить операцию, а вызвать её можно через `api_request`.

## Аргументы

- Параметры пути и запроса — обычные аргументы. Параметры JSON:API пишутся с точкой вместо скобок: `filter.bundleId` → `filter[bundleId]`, `fields.apps` → `fields[apps]`, `limit.builds` → `limit[builds]`.
- Массивы (`include`, `fields.*`, `filter.*`, `sort`) передаются JSON-массивами и уходят в запрос через запятую.
- Тело запроса — аргумент `body` (JSON-объект JSON:API: `{"data": {"type", "attributes", "relationships"}}`).
- Неизвестные, недостающие и неверные по типу или `enum` аргументы отклоняются до запроса.
- У операций с `include` есть `flatten: true`: связанные ресурсы из `included` подставляются на место ссылок `{type, id}`, атрибуты поднимаются на уровень ресурса, `included` и `links` убираются.
- У операций с двоичным ответом (отчёты продаж и финансов) обязателен `save_to` — путь нового локального файла. Удобнее скачивать отчёты [`report_download`](#report_download).

## Ответы и постраничная выдача

Ответ — документ JSON:API App Store Connect как есть. Если есть следующая страница или общее число записей, ответ оборачивается:

```json
{"result": {"data": []}, "pagination": {"next": "https://api.appstoreconnect.apple.com/v1/apps?cursor=…", "total": 42, "limit": 50}}
```

Следующая страница — `api_request` с `path`, равным `pagination.next` (полный адрес, только `GET` и только с хоста API). Когда часовая квота запросов почти исчерпана (осталось меньше 10 %), в обёртку добавляется `rate_limit` с `remaining` и `limit`. Если из ответа вырезаны секреты, обёртка получает поле `note` с пояснением.

Ошибки App Store Connect (`4xx`, `5xx`) возвращаются результатом с `isError: true`: статус, ошибки JSON:API (`code`, `detail`, `source`) и подсказка, что делать. Результат больше `--max-response-bytes` (256 КиБ по умолчанию) — ошибка с подсказкой сузить запрос (`fields.*`, `limit`, меньше `include`, `jq`).

## api_search и api_request

- `api_search` ищет по всем операциям API без обращения к нему: инструменты операций (включая невключённые наборы и инструменты выше уровня доступа), операции без своего инструмента и составные инструменты. Слова — на английском или русском («сборки testflight», «поэтапный релиз»). Каждый результат говорит, можно ли вызвать операцию на этом сервере и что её включает. Аргументы: `query`, `toolset`, `limit`; с `tool_name` — полное описание и схема одного инструмента.
- `api_request` вызывает любой путь API в пределах уровня доступа сервера (наборы его не ограничивают): метод `GET`, `POST`, `PATCH`, `PUT` или `DELETE`, относительный путь `/v1/…` (и `/v2/…`, `/v3/…`) или полный адрес `links.next`, `query`, `body` или `body_file`, `save_to`. Уровень берётся у операции, которой соответствует путь; для неизвестного пути — по методу. Полные адреса других хостов, `..` и `//` отклоняются, заголовки инструмент не принимает.

Подробности — в [справочнике CLI](cli.md#api_search-и-api_request).

## Фильтр jq

Инструменты операций с JSON-ответом, составные и пользовательские инструменты и `api_request` принимают необязательный аргумент `jq` — фильтр в диалекте [jaq](https://github.com/01mf02/jaq), например `[.data[] | {id, name: .attributes.name}]`. Фильтр применяется после вырезания секретов и `flatten`, постраничная обёртка остаётся снаружи, лимит размера действует на результат фильтра. Фильтры выполняются в отдельном процессе без окружения, файлов и сети, с таймаутом. Подробнее — [справочник CLI](cli.md#фильтр-jq).

## Составные инструменты

Составной инструмент делает несколько запросов к API (и к временным адресам, которые выдаёт API) за один вызов. Ответ проходит ту же обработку, что и ответы операций (вырезание секретов, `jq`, лимит размера), и собирается из выбранных полей: временных адресов загрузки, содержимого файлов, приватных ключей и паролей в нём нет. Все, кроме `release_status`, работают с [локальными файлами](security.md#локальные-файлы).

| Инструмент | Набор | Уровень | Что делает |
| --- | --- | --- | --- |
| [`release_status`](#release_status) | `versions-review` | чтение | Сводка релиза приложения на одной платформе. |
| [`metadata_export`](#metadata_export-и-metadata_apply) | `metadata` | чтение | Тексты страницы в App Store — в локальный каталог. |
| [`metadata_apply`](#metadata_export-и-metadata_apply) | `metadata` | запись | Отредактированный каталог — обратно в App Store Connect, с предварительным просмотром разницы. |
| [`asset_upload`](#asset_upload) | `media` | запись | Загрузка скриншота, превью, вложения и других медиа из файла. |
| [`build_upload`](#build_upload) | `builds` | запись | Загрузка сборки `.ipa` или `.pkg` без Transporter и altool. |
| [`report_download`](#report_download) | `analytics-reports` | чтение | Отчёт продаж, финансов или аналитики — в локальный файл со сводкой. |
| [`certificate_create`](#certificate_create) | `provisioning` | запись | Сертификат подписи без Keychain Access, по желанию — файл `.p12`. |
| [`profile_download`](#profile_download) | `provisioning` | чтение | Профиль подготовки — в файл и, на macOS, в каталог Xcode. |

### release_status

Сводка релиза за один вызов (ровно 4 параллельных запроса чтения): приложение (имя, bundle ID, SKU), опубликованная версия, версия в подготовке или на проверке с выбранной сборкой, типом выпуска и поэтапным выпуском, последняя отправка на проверку App Review и последние сборки TestFlight с состояниями обработки и бета-тестирования.

- Аргументы: `app_id` (обязателен; ID приложения в App Store Connect, не bundle ID), `platform` (`IOS` по умолчанию, `MAC_OS`, `TV_OS`, `VISION_OS`), `builds_limit` (1–50, по умолчанию 5).
- Ответ: `app`, `platform`, `live_version`, `pending_version`, `review`, `testflight_builds` и подсказки `next_steps` — какой инструмент вызвать дальше (выбрать сборку, ответить на вопросы экспортного контроля, отправить на проверку, выпустить версию).
- Нет версии в подготовке, отправок или сборок — это не ошибка: поле `null` или пустой список.

### metadata_export и metadata_apply

Работа с текстами страницы приложения в App Store через локальные файлы: выгрузить, отредактировать (вручную или агентом), посмотреть разницу и применить.

Формат каталога: файл `<locale>.json` на каждую локаль (`en-US.json`, `ru.json`) с разделами `version` (локализация версии: `description`, `keywords`, `marketingUrl`, `promotionalText`, `supportUrl`, `whatsNew`) и `appInfo` (локализация информации о приложении: `name`, `subtitle`, `privacyPolicyUrl`, `privacyChoicesUrl`, `privacyPolicyText`), плюс `_meta.json` с ID приложения, версии и appInfo и временем экспорта. Значение поля — строка или `null`.

`metadata_export` (чтение):

- Аргументы: `app_id` и `dir` (обязательны), `platform` (по умолчанию `IOS`), `version_id`, `app_info_id`.
- Без `version_id` берёт редактируемую версию платформы (состояния `PREPARE_FOR_SUBMISSION`, `DEVELOPER_REJECTED`, `REJECTED`, `METADATA_REJECTED`, `INVALID_BINARY`, `READY_FOR_REVIEW`), без `app_info_id` — редактируемую appInfo. Если подходящих нет или их несколько, возвращает список и просит указать ID.
- В каталог, где уже есть файлы локалей или `_meta.json`, не пишет. В ответе — список локалей и файлов, без самих текстов.

`metadata_apply` (запись):

- Аргументы: `dir` (обязателен), `dry_run` (по умолчанию `true`), `delete_missing_locales` (по умолчанию `false`), `version_id`, `app_info_id`.
- С `dry_run: true` ничего не отправляет и возвращает разницу: какие локализации будут созданы, какие поля изменятся (было → стало, короткое превью), каких локалей нет в файлах. С `dry_run: false` создаёт новые локализации и меняет только изменённые поля; повторный запуск без изменений ничего не пишет.
- Раздела или поля нет в файле — значение не трогается; `null` или пустая строка — поле очищается.
- До отправки проверяет длину полей в символах (название и подзаголовок — 30, ключевые слова — 100, промотекст — 170, описание и «Что нового» — 4000) и ссылки; при любой ошибке не отправляет ни одного запроса. Лимиты взяты из документации App Store Connect: спецификация API их не описывает.
- Версия и appInfo берутся из `_meta.json` и должны быть редактируемыми; явный `version_id` или `app_info_id` снимает эту проверку.
- Локали без файла удаляются только с `delete_missing_locales: true` и `dry_run: false` на сервере с `--allow-destructive`.
- Записи независимы: если одна не удалась, остальные выполняются, а ответ — ошибка с отчётом по каждой записи.

### asset_upload

Загружает локальный файл в App Store Connect одним вызовом: резервирует ресурс у родителя, отправляет файл частями по выданным Apple адресам, фиксирует его с контрольной суммой MD5 и (по умолчанию) ждёт окончания обработки.

- Аргументы: `resource` и `file` (обязательны), `parent_id`, `parent_relationship`, `file_name`, дополнительные атрибуты ресурса (`preview_frame_time_code`, `mime_type`, `app_event_asset_type`, `asset_type`), `wait` (по умолчанию `true`), `timeout_seconds` (по умолчанию 300, не больше 1800).
- `resource` — один из 21 вида ресурса: скриншоты (`appScreenshots`, родитель — набор скриншотов) и видеопревью (`appPreviews`), вложения для App Review, документы экспортного контроля, файлы routing app coverage, медиа внутриигровых событий, изображения App Clip, изображения и скриншоты для проверки покупок и подписок, изображения Game Center, файлы фоновых ресурсов. Полный список с типом родителя — в описании аргумента `resource` (`api_search` с `tool_name: "asset_upload"`).
- Ответ: ID ресурса, имя и размер файла, контрольная сумма, состояние обработки с предупреждениями и ошибками Apple. Временные адреса загрузки не возвращаются.
- Если часть или фиксация не удалась, незавершённое резервирование удаляется (только созданное этим вызовом). Если Apple не смогла обработать файл, ресурс остаётся, а ошибка называет его ID и инструмент удаления. Истёкший срок ожидания — не ошибка: ответ с текущим состоянием и инструментом для проверки.

### build_upload

Загружает сборку `.ipa` или `.pkg` через Build Upload API — замену Transporter и `altool`.

- Аргументы: `file` и `app_id` (обязательны), `platform` (`IOS`, `MAC_OS`, `TV_OS`, `VISION_OS`), `version`, `build_number`, `wait` (по умолчанию `true`), `timeout_seconds` (по умолчанию 1800, не больше 7200; относится только к обработке после загрузки).
- Версию и номер сборки инструмент берёт из `Payload/<имя>.app/Info.plist` внутри `.ipa`; для `.pkg` их нужно передать в `version` и `build_number`. Платформа — из аргумента, `Info.plist` или расширения файла. Bundle ID сверяется с приложением: расхождение — предупреждение.
- Ответ: ID загрузки, версия, номер сборки, платформа, состояние, ID сборки, когда Apple её свяжет, и подсказки. Ошибки обработки (подпись, уже использованный номер сборки) приходят ошибкой с текстом Apple; запись загрузки при этом остаётся, ошибка называет `delete_build_upload`. Если ждать дольше срока, инструмент подскажет проверить состояние через `get_build_upload`.
- Файл должен быть уже подписан для распространения: инструмент не подписывает и не экспортирует архивы.

### report_download

Скачивает отчёт в новый локальный файл (распакованный TSV/CSV, как его отдаёт Apple) и возвращает сводку вместо содержимого: путь, `rows`, `columns`, `bytes`, параметры отчёта и `summary` — диапазон дат, суммы `Units`/`Quantity`/`Counts`, число различных SKU и стран.

- `kind: "sales"` — отчёт Sales and Trends. Аргументы: `report_type` (по умолчанию `SALES`), `report_sub_type` (по умолчанию `SUMMARY`), `frequency` (`DAILY`, `WEEKLY`, `MONTHLY`, `YEARLY`; по умолчанию — по формату даты), `report_date` (`YYYY-MM-DD`, `YYYY-MM` или `YYYY`; без неё — последний доступный), `version`, `vendor_number`.
- `kind: "finance"` — финансовый отчёт за фискальный месяц: `report_date` (`YYYY-MM`, обязателен), `report_type` (`FINANCIAL` по умолчанию или `FINANCE_DETAIL`), `region_code` (по умолчанию `ZZ` для `FINANCIAL` и `Z1` для `FINANCE_DETAIL`), `vendor_number`.
- `kind: "analytics"` — отчёт App Analytics приложения `app_id`: из существующего запроса отчётов (сначала `ONGOING`; `access_type` выбирает тип), по `report_name` или `category`, экземпляры по `granularity` (по умолчанию `DAILY`) и `processing_date` или `date_from`/`date_to` (по умолчанию — последний экземпляр). Все сегменты склеиваются в один файл с одним заголовком.
- `save_to` обязателен и должен указывать на новый файл. Аргументы чужого `kind` отклоняются.
- Vendor number для продаж и финансов — из аргумента или профиля ([Vendor number](api-key.md#vendor-number-для-отчётов)). Отчёты продаж и финансов недоступны индивидуальным ключам.
- Инструмент только читает: запрос отчётов аналитики он не создаёт. Если у приложения запроса нет, его создают инструментом `create_analytics_report_request` (уровень записи), а первые данные Apple готовит 1–2 дня.
- Будущий или ещё не закрытый период отклоняется без запроса к API; «отчёт ещё не готов» и «данных нет» различаются в тексте ошибки. Содержимое отчёта и подписанные ссылки сегментов в ответ не попадают.

### certificate_create

Создаёт сертификат подписи без Keychain Access: ключ RSA 2048 и запрос на сертификат (CSR) генерируются локально, сертификат выпускает App Store Connect (`POST /v1/certificates`).

- Аргументы: `certificate_type` (обязателен; например `IOS_DISTRIBUTION`, `DISTRIBUTION`, `DEVELOPMENT`, `DEVELOPER_ID_APPLICATION`; перечисление — из спецификации), `common_name` (по умолчанию `appstore-connect-mcp`), `save_to`, `p12_password_file`, `pass_type_id`, `merchant_id`.
- Приватный ключ всегда сохраняется в системное хранилище секретов (сервис `dev.filipov.appstore-connect-mcp.secrets`, запись `<профиль>/certificate/<id>/private-key`) и не попадает в ответы.
- С `save_to` пишет новый `.p12` (сертификат и ключ; 3DES/SHA-1 PKCS#12, файл 0600), который принимают `security import`, Keychain Access, Xcode и OpenSSL. Пароль `.p12` — первая строка файла `p12_password_file`, иначе генерируется и сохраняется в хранилище (`<профиль>/certificate/<id>/p12-password`). Сам пароль в аргументы не передаётся.
- Ответ: ID сертификата, тип, имя, серийный номер, срок действия, имена записей хранилища и путь к файлу. Ключа, пароля, CSR и содержимого сертификата в ответе нет.
- Локальные проверки (путь, файл пароля, доступность хранилища) выполняются до выпуска: выпущенный сертификат отменяется только отзывом. Apple ограничивает число сертификатов каждого типа — если ответ сообщил, что сертификат создан, повторять вызов не нужно.
- Набор `provisioning` недоступен индивидуальным ключам.

### profile_download

Скачивает профиль подготовки по ID и сохраняет в новый файл `save_to` (`.mobileprovision`, для macOS — `.provisionprofile`).

- Аргументы: `profile_id` и `save_to` (обязательны; ID ресурса из `list_profiles`, не UUID), `install` (по умолчанию `false`).
- С `install: true` (только когда сервер работает на macOS) кладёт копию в каталог профилей Xcode 16 и новее `~/Library/Developer/Xcode/UserData/Provisioning Profiles/<UUID>.mobileprovision`. Такой же установленный профиль не трогает, другой файл с тем же именем не перезаписывает. Это единственное место, где сервер пишет вне [разрешённых каталогов](security.md#локальные-файлы).
- Ответ: ID, имя, тип, состояние, UUID, срок действия и записанные пути; содержимого профиля в ответе нет.

## Промпты

Сервер отдаёт три промпта (`prompts/list`) — готовые сценарии для частых задач. Промпт только описывает шаги для агента и называет инструменты; сам он запросов не делает. Необратимые шаги (отправка на проверку, публикация ответа, приглашение внешних тестировщиков) агент выполняет только после явного подтверждения пользователя, и эти инструменты требуют `--allow-destructive`.

| Промпт | Аргументы | Сценарий | Наборы |
| --- | --- | --- | --- |
| `prepare_release` | `app_id`, `platform`, `version` | Проверка перед отправкой версии на App Review: версия, сборка, метаданные во всех локалях, скриншоты, возрастной рейтинг, сведения для проверки, экспортный контроль, цены и доступность; отправка — после подтверждения. | `versions-review`, `apps`, `metadata`, `media`, `builds`, `pricing-availability` |
| `triage_reviews` | `app_id`, `days` (по умолчанию 30), `territory` | Свежие отзывы: группировка по темам и оценкам, черновики ответов; ответ публикуется только после одобрения точного текста. | `apps`, `reviews` |
| `testflight_distribution` | `app_id`, `build`, `groups` | Найти сборку, проверить обработку и экспортный контроль, задать «Что тестировать», добавить сборку в бета-группы и для внешних групп отправить на бета-проверку. | `apps`, `builds`, `testflight`, `versions-review` |

Обязателен только `app_id`. С динамическими наборами промпт подсказывает агенту включить нужные наборы через `enable_toolset`.

## Пользовательские инструменты

Частые запросы можно оформить своими инструментами: операция API с фиксированными аргументами и фильтром `jq` в `~/.config/appstore-connect-mcp/tools.toml`. Уровень доступа такого инструмента — уровень его операции. Формат и команды `tools list` и `tools check` — в [справочнике CLI](cli.md#tools).

## Частые задачи

| Задача | Инструменты |
| --- | --- |
| Что с релизом | `release_status` |
| Найти приложение | `list_apps` с `filter.bundleId` |
| Создать версию и выбрать сборку | `create_app_store_version`, `set_app_store_version_build` |
| Отредактировать описание и «Что нового» | `metadata_export` → правка файлов → `metadata_apply` |
| Загрузить скриншоты | `list_version_loc_screenshot_sets`, `asset_upload` с `resource: "appScreenshots"` |
| Загрузить сборку | `build_upload` |
| Отправить на проверку | `create_review_submission`, `create_review_submission_item`, `update_review_submission` (`--allow-destructive`) |
| Раздать сборку в TestFlight | промпт `testflight_distribution`, `list_beta_groups`, `add_beta_group_builds` |
| Отзывы | `list_app_customer_reviews`, `create_customer_review_response` (`--allow-destructive`) |
| Продажи за месяц | `report_download` с `kind: "sales"`, `report_date: "2026-10"` |
| Сертификат и профиль для CI | `certificate_create` с `save_to`, `profile_download` |

Если подходящего инструмента не видно, агент находит операцию через `api_search`.
