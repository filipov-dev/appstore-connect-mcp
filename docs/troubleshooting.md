# Решение проблем

Первым делом посмотрите, с чем запускается сервер и готов ли профиль:

```bash
appstore-connect-mcp serve --status --profile <профиль>   # без сети: ключ, уровень, наборы, каталоги
appstore-connect-mcp auth status --profile <профиль>      # ключ в хранилище и проверочный запрос к API
```

`serve --status` не выпускает JWT и не обращается к API; он показывает профиль, есть ли ключ (без значения), Key ID, Issuer ID, уровень доступа, наборы, режим динамических наборов, число инструментов, пользовательские инструменты и разрешённые каталоги. `auth status` дополнительно выполняет `GET /v1/apps?limit=1` и завершается ненулевым кодом, если профиль не готов.

## Homebrew не ставит формулу из стороннего tap

Устанавливайте по полному имени, а tap добавляйте с полным адресом: он размещён на SourceCraft, а не на GitHub.

```bash
brew tap filipov-dev/tap https://git.sourcecraft.dev/filipov-dev/homebrew-tap.git
brew install filipov-dev/tap/appstore-connect-mcp
```

## «no App Store Connect API key is stored for profile …»

Для профиля из `serve --profile` нет ключа в системном хранилище. Проверьте имя профиля в конфигурации клиента (`appstore-connect` — профиль `default`, `asc-<профиль>` — остальные) и сохраните ключ:

```bash
appstore-connect-mcp auth status --profile <профиль>
appstore-connect-mcp auth login --profile <профиль> --key-file ~/Downloads/AuthKey_ABC123DEFG.p8
```

Если файла ключа больше нет, создайте новый ключ в App Store Connect ([Ключ App Store Connect API](api-key.md)): скачать прежний повторно нельзя.

## Ключ отклонён: HTTP 401

`auth login`, `auth status` или `connect` пишут `App Store Connect rejected the key (GET /v1/apps?limit=1: HTTP 401)`, либо инструмент возвращает ошибку `HTTP 401` с подсказкой `The API key was rejected`. Причины:

- **Неверный Key ID.** Key ID должен совпадать с ключом, из которого взят файл: по умолчанию он берётся из имени `AuthKey_<KEYID>.p8`, поэтому переименованный файл даёт неверный ID. Передайте `--key-id` явно.
- **Неверный Issuer ID или тип ключа.** У командного ключа Issuer ID — над списком ключей в Users and Access → Integrations; у индивидуального ключа Issuer ID нет (`--individual`). Индивидуальный ключ, сохранённый как командный (и наоборот), отклоняется.
- **Ключ отозван** в App Store Connect. Создайте новый.
- **Часы компьютера сильно отстают или спешат.** JWT содержит время выпуска и истечения (срок — 15 минут); при большом расхождении времени Apple отклоняет токен. Включите синхронизацию времени (NTP).

Замените ключ и перезапустите сервер в клиенте (`/mcp` в Claude Code или перезапуск клиента):

```bash
appstore-connect-mcp auth login --profile <профиль> --key-file <AuthKey_XXXXXXXXXX.p8> \
    --issuer-id 00000000-0000-0000-0000-000000000000
```

## Нет доступа: HTTP 403

Ошибка `HTTP 403` у инструмента (подсказка `The API key's role does not allow this operation`) или `App Store Connect denied access` при проверке ключа:

- **Роли ключа не хватает.** Например, отчёты продаж требуют роли Sales, Finance или Admin, финансовые — Finance или Admin, пользователи и роли — Admin. Посмотрите роль ключа в Users and Access → Integrations и при необходимости создайте ключ с нужной ролью ([Роли](api-key.md#роли)).
- **Индивидуальный ключ.** Apple не даёт индивидуальным ключам доступа к Provisioning (сертификаты, профили, устройства) и к отчётам Sales и Finance — нужен командный ключ.
- **Ресурс другой команды.** Ключ видит только свой кабинет; для другого кабинета нужен отдельный профиль.
- **Нет vendor number или он чужой** (для `report_download` с `kind: sales` или `finance`): сохраните номер из Payments and Financial Reports — `auth login --vendor-number <номер>` ([Vendor number](api-key.md#vendor-number-для-отчётов)).

## Linux: Secret Service недоступен

В Linux ключ хранится через Secret Service (D-Bus); `libdbus-1` не нужна. Ошибка

```
the system keychain is not available: no Secret Service (org.freedesktop.secrets) is available on the D-Bus session bus …
```

при `connect`, `auth` или `serve` означает одно из:

- в сессии не запущен провайдер Secret Service — GNOME Keyring, KeePassXC (с включённой интеграцией Secret Service), KDE Wallet и т. п.;
- нет сессионной шины D-Bus: например, при входе по SSH на сервер без графической сессии;
- связка ключей заблокирована и разблокировать её некому.

Запасного файлового хранилища нет, и хранить ключ в переменной окружения или файле нельзя — это намеренное ограничение. На машине без графической сессии можно поднять шину и разблокированное хранилище вручную (пример для Debian/Ubuntu; в Alpine — пакеты `dbus gnome-keyring libsecret`):

```bash
sudo apt-get install dbus-daemon gnome-keyring libsecret-tools
dbus-run-session -- sh
# внутри новой оболочки: введите пароль связки ключей и нажмите Ctrl-D
gnome-keyring-daemon --unlock --components=secrets
appstore-connect-mcp auth login --key-file AuthKey_ABC123DEFG.p8 --issuer-id 00000000-0000-0000-0000-000000000000
appstore-connect-mcp auth status
```

Хранилище живёт, пока жива эта сессия D-Bus: MCP-клиент, который запускает `appstore-connect-mcp serve`, должен работать внутри неё. Проверить, что ключ сохранён, не показывая его: `appstore-connect-mcp auth status --no-verify`. Удобнее запускать агента на рабочей машине с графической сессией.

## Linux: ошибка проверки сертификата

Сертификат App Store Connect API проверяется по корневым сертификатам системы. Если запросы падают с ошибкой TLS или сертификата, поставьте пакет `ca-certificates` (в минимальных образах — Debian/Ubuntu slim, Alpine — его нет) или укажите файл сертификатов в переменной `SSL_CERT_FILE`.

## macOS: Keychain спрашивает разрешение

macOS может спросить, разрешить ли `appstore-connect-mcp` доступ к записи `dev.filipov.appstore-connect-mcp` в связке ключей — обычно когда ключ сохранила одна сборка бинарника, а читает другая. Нажмите «Всегда разрешать», иначе вопрос будет повторяться при каждом запуске сервера.

Бинарник из Homebrew и релизных архивов подписан Developer ID, поэтому после обновления разрешение, как правило, сохраняется. Бинарник, собранный из исходников, не подписан: после пересборки macOS может считать его новой программой и спросить снова.

Когда сервер запускает MCP-клиент, окно с вопросом появляется поверх других окон, а клиент ждёт ответа. Если клиент пишет, что сервер не запустился или не ответил, проверьте, нет ли такого окна. По SSH связка ключей входа может быть заблокирована: разблокируйте её (`security unlock-keychain`) или выполните `connect` в обычном сеансе.

## Агенту не хватает инструмента

Вызов незарегистрированного инструмента по имени возвращает ошибку с причиной:

- `tool … is disabled: it creates or changes data … and the server runs with read-only access` — сервер работает на более низком уровне доступа. Поднимите уровень профиля: `appstore-connect-mcp ui` (вкладка Access) или `connect … --allow-write`, затем перезапустите клиент. На macOS проверьте одобрение: `appstore-connect-mcp serve --status --profile <имя>` показывает строку `Approval`, а сервер без одобрения пишет предупреждение в stderr. Список действий уровня удаления — в [MCP-инструментах](tools.md#уровни-доступа).
- `tool … belongs to toolset …, which is not enabled` — набор не включён. С динамическими наборами агент включает его сам через `enable_toolset`; без них добавьте набор в `--toolsets` (или `--toolsets all`). Операцию в пределах уровня доступа можно вызвать и через `api_request` — ошибка называет метод и путь.
- Операции нет среди инструментов вовсе (устаревшая, чтение идентификаторов связей, дубль списка): `api_search` найдёт её, скажет, чем её заменить, и её можно вызвать через `api_request`.
- С динамическими наборами клиент не показывает новые инструменты после `enable_toolset`: не все клиенты перечитывают список по `notifications/tools/list_changed`. Агент может вызывать те же операции через `api_request`, или подключите сервер без динамических наборов (`connect … --no-dynamic-toolsets`).

Какие наборы и сколько инструментов включено, показывает `appstore-connect-mcp serve --status`; все наборы с числом инструментов — `appstore-connect-mcp toolsets`.

## Ответ слишком большой

Результат больше `--max-response-bytes` (256 КиБ по умолчанию) возвращается ошибкой с подсказкой сузить запрос:

- запросите только нужные атрибуты: `fields.<тип>` (например, `fields.apps: ["name", "bundleId"]`);
- уменьшите страницу (`limit`) и число связей в `include`;
- уточните фильтры `filter.*`;
- выберите нужное фильтром `jq` — лимит действует на результат фильтра;
- большие файлы (отчёты, профили, сертификаты) сохраняйте через `save_to` или составные инструменты.

Лимит можно увеличить флагом `--max-response-bytes` в аргументах сервера. Если ответ изменяющего запроса не поместился, ошибка прямо говорит, что запрос выполнен и повторять его не нужно.

## Квота запросов: HTTP 429

App Store Connect ограничивает число запросов в час на ключ. Сервер сам повторяет запрос после `429` с учётом `Retry-After` (до трёх раз, пауза не больше 30 секунд); если квота исчерпана надолго, инструмент возвращает ошибку `Rate limited: the hourly request quota is used up; retry later` с остатком квоты. Когда осталось меньше 10 % квоты, ответы содержат поле `rate_limit` — агенту стоит делать меньше запросов: запрашивать списки страницами побольше и только нужные поля, пользоваться `release_status` вместо серии запросов.

## Ошибки сервера Apple: HTTP 5xx

Запросы `GET`, `PUT` и `DELETE` после `500`, `502`, `503` и `504` сервер повторяет сам. `POST` и `PATCH` не повторяются, чтобы не создать ресурс дважды: проверьте, выполнилось ли действие (например, списком ресурсов), прежде чем повторять.

## Файл «is outside the allowed directories» или «already exists»

Инструменты работают с локальными файлами только в рабочем каталоге сервера, системном временном каталоге и каталогах `allow_path` профиля. Если клиент запускает сервер в домашнем каталоге или в `/`, рабочий каталог не разрешён. Добавьте нужный каталог в права профиля: `appstore-connect-mcp ui`, вкладка Access, клавиша `a` ([Безопасность](security.md#локальные-файлы)).

Скачивание никогда не перезаписывает существующий файл: укажите новое имя в `save_to` (или пустой каталог в `dir` для `metadata_export`).

## Загрузка или обработка не закончилась

`asset_upload` и `build_upload` по умолчанию ждут, пока Apple обработает файл. Если срок ожидания (`timeout_seconds`) вышел, это не ошибка: ответ содержит текущее состояние и инструмент для проверки позже (`get_build_upload` для сборок). Если загрузка частей не удалась, незавершённое резервирование удаляется; если Apple не смогла обработать файл (`FAILED`), ошибка содержит тексты Apple, а ресурс остаётся — его можно удалить инструментом, который называет ошибка.

## Клиент не видит сервер или его инструменты

- Перезапустите клиент после `connect` или правки конфигурации.
- Укажите в конфигурации клиента абсолютный путь к бинарнику (`command -v appstore-connect-mcp`).
- Запустите команду из конфигурации вручную, например `appstore-connect-mcp serve --profile default`. Ошибки запуска (нет ключа, недоступно хранилище, неизвестный набор, флаг доступа сверх прав профиля, каталог `--allow-path` вне каталогов профиля) печатаются в stderr, в stdout при этом ничего нет. Если ошибок нет, сервер ждёт сообщений MCP на stdin — остановите его `Ctrl-C`.
- Для подробных логов добавьте в аргументы сервера `--log-level debug`. Логи пишутся только в stderr, ключ и JWT в них не попадают.
- Если имя сервера длиннее 17 символов, клиент может укоротить или отклонить часть инструментов ([Имя сервера](clients.md#имя-сервера)).

## Запрос отклонён: HTTP 400, 409, 422

App Store Connect отклонил аргументы или тело запроса. Ошибка содержит `code`, `detail` и `source` каждой ошибки JSON:API: `source` называет неверное поле или параметр. Сверьте аргументы со схемой инструмента (`api_search` с `tool_name`). Тело передаётся в `body` объектом JSON:API (`{"data": {"type", "attributes", "relationships"}}`), параметры запроса — с точкой вместо скобок (`filter.app`).
